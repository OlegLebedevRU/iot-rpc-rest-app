# 🔔 Webhooks · События и результаты

> Push-уведомления организации о новых событиях устройств и сохранённых RPC-результатах.

[← REST API](rest-api.md) · [Задачи](1-task-workflow-doc.md) · [События](2-events-api-format-description.md)

## 🧭 Две подписки

| Тип | Когда отправляется | Конечный URL |
| :--- | :--- | :--- |
| `msg-event` | Новое сохранённое обычное событие | `{registered_url}/{device_id}` |
| `msg-task-result` | Новый сохранённый результат, допустимый по правилам lifecycle | `{registered_url}/{task_uuid}` |

Webhook сообщает о данных, а не о каждом переходе состояния задачи. Gauges, дубликаты и transport probes не создают новые уведомления.

## ⚙️ Настройка

Базовый путь: `{base_url}/api/v1/webhooks`. Ключ организации определяет владельца подписки.

| Метод | Путь | Назначение |
| :--- | :--- | :--- |
| `GET` | `/` | Список подписок организации |
| `PUT` | `/{event_type}` | Создать или обновить URL, headers и активность |
| `DELETE` | `/{event_type}` | Удалить подписку |

```http
PUT /api/v1/webhooks/msg-task-result
x-api-key: <organization-api-key>
Content-Type: application/json
```

```json
{
  "url": "https://example.com/hooks/task-result",
  "headers": {"Authorization": "Bearer <receiver-secret>"},
  "is_active": true
}
```

`url` обязателен, должен быть HTTP(S); для внешнего приёмника используйте HTTPS. `headers` — объект строк или `null`, `is_active` по умолчанию `true`. Поддерживаются только два типа из таблицы. Отключить без удаления можно через PUT с `is_active=false`.

Ответ содержит `org_id`, `event_type`, `url`, `headers`, `is_active`, `created_at`, `updated_at`. DELETE возвращает `{"message":"Webhook deleted"}`, отсутствие подписки — `404`.

## 📦 HTTP-конверт

### Результат задачи

```http
POST /hooks/task-result/5c75b4ed-2488-4769-b23a-2afae64ea22d
Content-Type: application/json
x-msg-type: msg-task-result
x-device-id: 4619
x-ext-id: 77
x-result-id: 304
x-status-code: 200
```

```json
{"status":"OK"}
```

Тело — сохранённый результат, а не полный объект задачи и не массив `results`. UUID берётся из пути, ID результата — из `x-result-id`. Для полного состояния используйте GET задачи. Чувствительные поля результата рекурсивно маскируются перед сохранением.

### Событие устройства

```http
POST /hooks/events/4619
Content-Type: application/json
x-msg-type: msg-event
x-device-id: 4619
```

```json
{
  "101": 20338,
  "102": "2026-10-09T08:00:00Z",
  "200": 13,
  "300": [{"304": 5}]
}
```

Тело — JSON устройства. REST-конверт `DevEventOut`, серверный event `id` и времена хранения к нему не добавляются. Настроенные headers включаются в запрос; системные `x-*` поля задаёт платформа.

## 🔄 Доставка и устойчивость

| | RPC-результаты | События |
| :--- | :--- | :--- |
| Планирование | Запись доставки создаётся в одной транзакции с результатом при существующей активной подписке | Новый EVT передаётся в брокерную очередь webhook |
| Повторы | После временной ошибки: 5, 15, 45, 120, 300 секунд; не более 6 попыток в пределах срока доставки | HTTP retry по настройкам клиента; по умолчанию 3 повтора после первой попытки |
| После рестарта | Планирование результата сохраняется в PostgreSQL | Зависит от очереди и обработки сообщений |
| Дедупликация приёма IoT | Повтор RES не создаёт новую доставку | Повтор EVT не создаёт новый webhook |

Retry выполняется для сетевых ошибок, `408/425/429` и `5xx`; остальные HTTP-ошибки терминальные. Срок доставки результата — 30 минут по текущей модели. Отключение подписки или окончание срока прекращает дальнейшие попытки. Создание подписки после результата не запускает replay старых результатов.

Приёмник должен принимать повторные HTTP-запросы: успешная обработка может произойти до потери HTTP-ответа. Для результатов используйте `x-result-id`, для событий — устройство, `101` и время события. Внешние бизнес-действия выполняйте идемпотентно.

Подтверждайте приём кодом `2xx` после надёжного сохранения у себя. Проверяйте секрет из настроенных headers; встроенная HMAC-подпись этим API не предоставляется. История REST остаётся способом сверки и восстановления пропущенных уведомлений.

## ⏱️ Поздний результат

Новый результат EXPIRED-задачи создаёт уведомление, если получен не позднее трёх минут после её deadline и есть активная подписка. Позже он только сохраняется и получает MQTT CMT. После DELETE новый webhook не создаётся. Уже запланированные доставки имеют собственный lifecycle. [Полные правила TTL](TTL.md).
