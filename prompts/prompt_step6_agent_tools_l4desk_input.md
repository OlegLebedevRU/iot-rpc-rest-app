# Задание 1 (Шаг 6): l4desk / l4superv — Проверенные права и безопасный ввод

## 1. Роль и scope

Ты Windows / C Systems Developer. Работай минимальными изменениями Win32, без нового брокера привилегий, драйвера, `uiAccess` или обязательной Authenticode-подписи.

Обязателен [обзор шага 6](prompt_step6_stacks_overview.md), особенно разделы 2 и 4. Это требования к реализации, не утверждение о возможностях текущего агента.

Точки входа (проверить фактические файлы/символы до изменения):
- `tools\l4superv\src\session_proc.c` — запуск и остановка в сессии;
- `tools\l4desk\src\input_inject.c`, `input_inject.h` — ввод и release;
- `tools\l4desk\src\ctl_protocol.c`, `ctl_protocol.h` — парсинг, lease, dedup, ACK/NACK;
- `tools\l4desk\res\l4desk.manifest` — `asInvoker`, `uiAccess="false"`;
- существующий владелец FFmpeg — захват, курсор и жизненный цикл;
- `tools\l4desk\build.cmd`, `tools\l4superv\build.cmd` и релевантные тесты.

MQTT-клиент/presence не менять молча: до реализации выполнить опрос типа и согласование расширения по обзору. Не занимать другой retained-топик. Версии всех компонентов централизованно меняет агент 4; серверная сторона протокола принадлежит [агенту 2A (app1)](prompt_step6_agent_iot_rpc_rest_app_quick_actions.md), UI/BFF — [агенту 2B (MenuBuilder)](prompt_step6_agent_menubuilder_quick_actions.md), lifecycle — агенту 3. Результат 1 передается в 2A до реализации app1; затем результат 2A используется в 2B.

## 2. Запуск без скрытого повышения прав

### 2.1. Матрица токенов вместо безусловного TokenLinkedToken

1. Подтвердить, что `l4superv` работает как LocalSystem с правами, нужными `WTSQueryUserToken` и `CreateProcessAsUserW`. Не переносить эти привилегии пользователю киоска.
2. Выбирать целевую активную **консольную** сессию по существующей политике. Session 0, отсутствие пользователя, disconnected/RDP вместо консоли — не подходящая замена. Обрабатывать смену сессии между проверкой и запуском.
3. Получить пользовательский токен, проверить `TokenElevationType`, `TokenIntegrityLevel`, `TokenSessionId` и SID пользователя:
   - `Limited`: если профиль требует High IL, запросить `TokenLinkedToken` и проверить его фактическое повышение, пользователя и сессию;
   - `Full`: использовать уже полный токен, не переключаться на связанный ограниченный;
   - `Default`: проверить реальные права/IL, не предполагать наличие linked token;
   - обычный пользователь + требование High IL: `insufficient_integrity`. Не использовать SYSTEM/чужой токен, пароли, `runas`, scheduled task для обхода, отключение UAC или повышение учетной записи.
4. `DuplicateTokenEx` с минимально необходимыми правами, первичный токен. `CreateProcessAsUserW` с явным `lpApplicationName`, абсолютным защищенным путем, корректно экранированными аргументами, `winsta0\default`, пользовательским environment и заданным рабочим каталогом. Не наследовать лишние handles; закрывать токены, process/thread handles, environment на всех ветках.
5. Проверить SID/session/IL запущенного агента, а не считать успешный WinAPI-вызов доказательством High IL. Нет необходимых прав — конечный диагностируемый отказ без диалога, не перезапуск каждую секунду.
6. В службе нет интерактивных окон; дочерние консольные процессы не вспыхивают на экране. Установщик проверяет ACL бинарников/конфигурации/IPC; привилегированный агент не принимает произвольный путь или команду из сети.
7. Настроить error mode собственных процессов/помощников (`SetErrorMode`, в том числе `SEM_FAILCRITICALERRORS` / `SEM_NOGPFAULTERRORBOX` там, где применимо) и проверить реальный crash/startup-failure без модального окна. Не отключать WER/защиты всей Windows; ошибка остается в диагностике и recovery.

## 3. Desktop guard и безопасная политика

- Применять общий gate ко **всем** путям ввода, не только к `shortcut_action`: lease, scope, desktop stream, source, SN, epoch, TTL, сессия, input desktop, локальная политика.
- Использовать `OpenInputDesktop` и `GetUserObjectInformationW(UOI_NAME)` совместно с состоянием сессии; handle закрывать через `CloseDesktop`. Доступ разрешен только к нужному `default`; ошибка доступа означает запрет. `GetThreadDesktop` для этой проверки недостаточен, особенно при блокировке/отключении.
- Не открывать/переключать `Winlogon`, не менять desktop DACL, не синтезировать SAS, Win+L, logout/shutdown. При смене desktop остановить ввод и пометить видео недоступным; не показывать старый кадр как текущий.
- `alt_f4` / `win_d` запрещены локально по умолчанию. `f12` — только в проверенном профиле приложения; это не универсальная безопасная «диагностика».
- Если для отдельного обслуживания разрешен `alt_f4`, проверить цель: HWND, PID и путь процесса, не системная оболочка, не основной процесс киоска, явно разрешенное приложение. Дополнительно исключить `Progman`, `WorkerW`, `Shell_TrayWnd`, `Shell_SecondaryTrayWnd`, `GetShellWindow`, неизвестный/исчезнувший HWND.
- Повторить проверку фокуса перед инъекцией; смена цели — `action_blocked_winlogon_guard`. Это уменьшает гонку, но **не делает SendInput адресным/атомарным**. Если профиль требует абсолютного запрета выхода, не разрешать Alt+F4 вообще.
- `win_d` не закрывает окна, но открывает desktop и может нарушить киоск. Даже в обслуживании разрешать только для проверенной Explorer-shell конфигурации, не как «восстановление» custom shell.
- Не обходить ограничения через обычные `key_event`, отдельные down/up, сочетания с уже удерживаемыми модификаторами или альтернативный API. Сохранять whitelist; при неизвестном состоянии клавиш отклонять рискованную комбинацию.

## 4. Клик, шорткаты и результаты

### 4.1. Один последовательный исполнитель ввода

- Нормализованный и абсолютный click используют общий проверенный путь: `SendInput(2, MOVE + DOWN)` → `Sleep(40)` → `SendInput(1, UP)`.
- Публичные кнопки только `left` / `right`, default `left`; правая — `MOUSEEVENTF_RIGHTDOWN` / `MOUSEEVENTF_RIGHTUP`. Локальную поддержку middle не путать с публичным контрактом.
- `f12`: F12 down → пауза → up. Для разрешенных профилем `alt_f4` / `win_d`: modifier down → key down → пауза → key up → modifier up.
- Проверять возвращенное число событий на каждой стадии, учитывать частичное выполнение. ACK `injected` только после полного успешного цикла. Локально наблюдаемая пауза не обязана быть ровно 40 мс из-за планировщика Windows.
- Сериализовать команды ввода существующим простым механизмом; не спать на MQTT callback/keepalive потоке. Не создавать неограниченную очередь: просроченный ввод отбрасывать до исполнения.
- Отслеживать только собственные нажатия. При ошибке, отмене, потере lease/сессии — безопасный release по существующему механизму. Не отпускать вслепую физические клавиши пользователя, не повторять DOWN/клик «для надежности».
- Если desktop сменился между DOWN и UP, нельзя гарантировать отпускание на защищенном desktop: ввод заблокировать, сохранить cleanup-состояние и безопасно обработать его при возвращении того же доступного desktop. Не переносить удержания/очередь в новую сессию и не выдавать такой клик за успех.
- При нуле/частичном `SendInput` сообщать `input_injection_failed`; не диагностировать UIPI только по `GetLastError`. Не повторять действие после timeout; корреляция и dedup сохраняются.

### 4.2. Видео и курсор

- High IL не гарантирует захват всех окон: `gdigrab` проверять на обычном и повышенном приложении в том же доступном desktop. Secure desktop, protected content и чужие сессии вне scope.
- Проверить фактическую настройку отрисовки курсора FFmpeg (`draw_mouse`) и соответствие координат видео/виртуального экрана. Не добавлять второй курсор, если он уже встроен в кадр; локальный маркер оператора не считать доказательством положения системного курсора.
- При блокировке/потере сессии — явная недоступность и остановка/восстановление по существующему lifecycle. Истекшая lease не должна восстанавливать поток автоматически.

## 5. Жизненный цикл без администратора

- SCM восстанавливает службу; `l4superv` — единственный владелец рестартов l4desk; FFmpeg остается у существующего владельца. Не вводить конкурирующие watchdog или задачу планировщика.
- Сбой процесса: ограниченное число попыток с задержками и диагностикой; штатный stop, drainage, отсутствие сессии, истекшая lease не являются crash. Пределы существующего recovery явно передать в приемку, при их отсутствии задать конечные значения до реализации.
- Stop l4superv для upgrade должен отключать его recovery и завершать только собственных дочерних процессов. Передать агенту 3 доказуемый контракт владения/остановки, не `kill` по имени.
- После рестарта/смены сессии нет старых нажатий, старой lease, старого FFmpeg или автоматического включения ввода.

## 6. Проверки и Definition of Done

1. Для исправляемых багов сначала воспроизведение до правки. Тесты выбора токена: Limited/Full/Default, standard user, отказ linked token, неверный SID/session/IL, отсутствие консоли; ни одна ветка не вызывает elevation UI.
2. Тесты input gate: locked/unavailable desktop, RDP/disconnected, stale lease/epoch/TTL, duplicate command, unknown button/action, неправильный scope. Запрет опасных действий нельзя обойти `key_event`.
3. Тесты инъекции с проверяемым WinAPI-адаптером: порядок down/up, пауза, правый клик, partial failure, cleanup, смена фокуса/desktop, задержка не блокирует renew. Моки проверяют логику, **не доказывают** поведение Windows.
4. Выполнить штатные x86/x64 `/MT` сборки обоих компонентов и все относящиеся native/integration-тесты, включая dedup, ACK, lease expiry, recovery/reconcile. Не запускать несвязанные backend/frontend проверки для tools-only изменений.
5. На выделенном стенде подтвердить реальный IL, клики по повышенному окну, курсор, безопасные отказы, отсутствие окон/зависших клавиш, восстановление без restart storm. Полная матрица — у [агента 5](prompt_step6_agent_stand_verification.md).
6. Передать агентам 2A/2B фактические ACK/NACK, схемы/fixtures consumer, совместимость старого агента, политику shortcuts и результаты тестов; агенту 3 — контракт stop/restart и относящиеся к нему результаты. Непроверенные OS/профили отметить как непроверенные, а не «поддерживаются по умолчанию».
