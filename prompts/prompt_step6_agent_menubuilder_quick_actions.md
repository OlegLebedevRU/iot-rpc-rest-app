## 2. Сквозной контракт и ограничения

### 2.1. Сообщения UI

```json
{
  "type": "mouse_click",
  "x": 32768,
  "y": 32768,
  "button": "right",
  "client_ref": "<uuid-v4>"
}
```

```json
{
  "type": "shortcut_action",
  "action": "f12",
  "client_ref": "<uuid-v4>"
}
```

- `button`: `left` / `right`, при отсутствии `left`; middle не входит в расширение. `action`: `f12` / `alt_f4` / `win_d`. Координаты — целые `0..65535`; неизвестные значения и нецелые/внедиапазонные координаты — отказ.
- UI не задает доверенные owner, SN, scope, `command_id`, lease и эпоху. BFF проверяет JWT, организацию, доступ к устройству и входные схемы. `org_id` приводится к `int` на границе авторизации.
- По контракту 2A `app1` проверяет владельца lease, scope `input`, активный desktop stream, source/epoch, TTL и политику; формирует envelope из обзора в `srv/{SN}/ctl`. BFF передает доверенный контекст штатным внутренним API и не публикует в MQTT напрямую. Проверки app1 не заменяют авторизацию BFF.
- Права проверяются одинаково для WS и REST fallback; camera/view-only не допускает ввод. Нельзя ослабить запрет через прямой WS, устаревшую lease или обычный `key_event`.
- Действия не retained, dedup по `command_id`. Потерянный ACK означает неизвестный результат, не разрешение повторить клик. UI/BFF/app1 не делают автоматический retry ввода при timeout/reconnect.
- Новые действия включать только при подтвержденной совместимости consumer через существующие version/capability сведения. Неизвестная/старая версия — недоступные новые кнопки с причиной, без fallback в произвольные клавиши. Не строить отдельный capability framework ради этого шага.

### 2.2. ACK/NACK и доверие результату

- Сохранить существующий envelope ответа и корреляцию `command_id ↔ client_ref`, lease/epoch по результату 2A, согласованному с агентом 1. Нельзя показывать поздний ACK прежней сессии как результат текущей команды. HTTP-принятие запроса или MQTT PUBACK не означает `injected`.
- `injected` означает только принятие событий Windows: текст `Ввод передан терминалу`, а не `Окно закрыто` или `Меню открыто`. Не показывать success-toast на каждый клик.
- `action_blocked_policy`: `Действие запрещено настройками киоска`.
- `action_blocked_winlogon_guard`: `Действие отклонено: небезопасное или изменившееся активное окно`.
- `desktop_locked`, `session_unavailable`, `insufficient_integrity`: показать причину недоступности; не предлагать нажать UAC, разблокировать терминал или войти в Windows через remote input.
- `input_injection_failed` / timeout: `Результат ввода не подтвержден. Проверьте изображение перед повторным действием.` Автоматического повтора нет.
- Результат показывать компактным статусом последней команды; важные отказы — ненавязчивым уведомлением. Не маскировать отказ optimistic success.

## 3. UI без выхода из киоска по умолчанию

- Панель расположить вне координатной области ввода, не перекрывая платежные элементы на видео. Клики/подтверждения в панели не должны всплывать до обработчика remote mouse.
- Действия доступны только при подтвержденной активной input lease, desktop stream и известной совместимости агента; отключать при потере прав/сессии/эпохи и в процессе остановки потока.
- `Alt+F4` и `Win+D` по умолчанию отключены на рабочем киоске с объяснением. Отдельный подтвержденный профиль обслуживания может разрешить их; браузер не включает локальную политику терминала по своему желанию.
- Для разрешенного `Alt+F4` показать оператору подтверждение `Закрыть разрешенное активное окно? Это может прервать его работу.` Подтверждение находится **в браузере оператора**, не на киоске, и не отменяет терминальные guards. Разрешенный `Win+D` тоже требует предупреждения о показе рабочего стола.
- `F12` доступен только для проверенного профиля приложения; tooltip не обещает, что он откроет консоль разработчика на любом терминале.
- Правый клик: ровно один `mouse_click(button="right")`; подавлять браузерное контекстное меню только внутри активной области удаленного ввода. Не отправлять действие одновременно из `pointerup` и `contextmenu`. Клик по полосам видео/панели не уходит на терминал.
- Сохранить существующие Design Tokens Ant Design и доступность по клавиатуре. Нет очереди действий во время reconnect и нет серии модальных окон после восстановления.

## 4. Таймауты BFF

- В `config.py` разделить `iot_rpc_stream_start_timeout_seconds = 20.0` и `iot_rpc_inventory_timeout_seconds = 35.0`, **если в результате 2A подтверждены** upstream budgets 15/30 с; иначе согласовать значения с агентом 2A по реальному `app1`, не менять upstream в рамках этого задания.
- Использовать их соответственно в `remote_input_stream_start` и `remote_input_get_inventory`. Они не относятся к startup служб 120 с и не должны увеличивать TTL пользовательского ввода.
- `httpx.TimeoutException` → HTTP `504`, тело с `code: "terminal_timeout"` и безопасным пояснением. Не превращать auth/connection/protocol errors в timeout, не терять исходные 4xx/5xx. Сам по себе upstream timeout не доказывает, что виноват терминал.
- Не добавлять скрытые retry для input или запуска потока; UI получает честное неизвестное/неуспешное состояние по существующему lifecycle.
