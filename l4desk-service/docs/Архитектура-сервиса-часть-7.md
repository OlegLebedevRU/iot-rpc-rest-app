### Итерация 7 — оценка полноты понимания

Да, **основная архитектура, границы компонентов и коммерческая логика уже понятны достаточно полно**. Можно переходить к финальному документу после закрытия нескольких точечных правил. Масштабных неизвестных, требующих пересмотра решения, я не вижу.

Ваше уточнение по трём отложенным дням понимаю так:

```text
cycle_start = индивидуальная граница цикла
grace_deadline = cycle_start + 3 дня
```

Grace привязан к границе цикла, а не к моменту ухода баланса в минус.

Пример:

```text
Граница цикла:                  01.10 00:00
Окончание допустимой отсрочки:  04.10 00:00
Первый online терминала:        05.10
Начисление terminal-month:      100 руб. за текущий цикл
Баланс недостаточен:            сервис блокируется сразу
```

При последующей оплате:

- задолженность за текущий цикл погашается;
- текущий месяц считается уже начавшимся с исходной границы;
- новая граница не переносится на дату online или оплаты;
- оплаченный терминал разблокируется;
- следующий цикл начнётся по прежнему индивидуальному якорю.

Если баланс на момент online достаточен, `100 руб.` списываются и терминал работает без grace/blocking.

### Итоговая формула допуска после первой оплаты

Для платного терминала при первом online в цикле:

```text
1. Идемпотентно создать terminal-month charge.
2. Пересчитать fin_balance_projection.
3. Если balance >= 0:
       разрешить работу.
   Иначе если now < cycle_start + 3 days:
       разрешить в режиме grace.
   Иначе:
       зафиксировать blocked и не запускать console/video.
```

Для уже активной сессии при наступлении `grace_deadline`:

- video/remote control завершается штатным stop-flow;
- console перестаёт принимать новые команды;
- текущая команда получает ответ либо timeout;
- затем console-сессия закрывается.

До первой оплаты grace отсутствует: доступен только бесплатный пакет.

### Зафиксированные решения

- Расчётный цикл индивидуален и якорится на первой успешной оплате.
- Первый терминал бесплатен; при удалении льгота переходит к следующему по номеру.
- Каждый следующий терминал стоит `100 руб.` за цикл, если хотя бы один раз был online.
- Online не переносит границу цикла.
- Console и video взаимоисключающие.
- Общая бесплатная квота первого терминала — `120 минут/сутки` по timezone тенанта.
- Платное время агрегируется посуточно и округляется вверх до целого часа.
- Итоговое начисление округляется вниз до целого рубля до проводки; отброшенные копейки сохраняются в расчётной расшифровке.
- `MenuBuilder` владеет `fin_*` subledger, балансом, тарифами, ЮKassa и entitlement.
- `iot-rpc-rest-app` владеет MQTT/RabbitMQ, RPC, техническими session facts, блокировкой конкурентных сессий и graceful stop.
- `tools`/Агент сохраняет обратную совместимость существующих MQTT/RPC-контрактов.
- Консоль и видео имеют одну реализацию для существующих и новых пользователей `MenuBuilder`.
- Оплаты физлиц — ЮKassa; оплаты юрлиц вручную проводит один superuser через неизменяемый документ и сторно.
- Финансовое ядро и агрегаты не удаляются при оперативной архивации.
- Массовые технические подробности старше трёх полных месяцев архивируются пакетами.
- Архив хранится на смонтированном томе хоста.
- Финансовая история хранится не менее `3 лет`.

### Архивирование на смонтированный том

Для MVP достаточно следующей безопасной процедуры:

```text
/export/archive/<year>/<month>/<project>/<archive_batch_id>/
  data.jsonl.gz
  manifest.json
  checksum.sha256
```

Порядок:

1. Проект формирует временный архив закрытого календарного месяца.
2. `manifest` содержит таблицы/типы событий, количество строк, диапазон времени и версии схем.
3. Рассчитывается `SHA-256`.
4. Архив повторно читается и сверяется с manifest.
5. Выполняется атомарное переименование временного каталога в итоговый.
6. В БД archive batch получает состояние `verified`.
7. Только после этого удаляются массовые горячие подробности.
8. Финансовый ledger, платежи, расчётные агрегаты и итоговые session rows остаются в БД.

Для защиты от потери том с архивами должен входить в штатное резервное копирование. Сам факт наличия файла на томе резервной копией не является.

Из предыдущих ответов я понимаю это как **жёсткий суточный предел без платного продления**, но прошу подтвердить.

2. Какой online-факт считается достаточным для начисления `100 руб.`: первое аутентифицированное presence-событие Агента в `iot-rpc-rest-app`, даже если соединение длилось несколько секунд?
